## 별도 오류

world 3 종료 뒤 방 이탈 과정에서 호스트와 게스트 모두 `RequestNightEndDropAsync` 객체 요청 timeout을 기록했다. 게스트는 이후 world 4/대기실 정리 중 `GameInstance에 UIRoot가 연결되지 않았습니다` 예외도 기록했다. 두 오류는 정상 플레이 world 3 입력 집계 이후에 발생했으며, 입력 생성·2001 역직렬화·Publish 오류나 송신 실패는 확인되지 않았다. 이동 기준선과 분리해 추적한다.

## 플레이 관찰과 원격 표시

사용자는 게스트 화면에서 한 번 떨림을 관찰했고, 호스트 화면에서 게스트 캐릭터가 로컬 캐릭터보다 조금 덜 부드럽게 이동했다고 보고했다. 따라서 입력 수치 기준선 통과를 원격 표시 부드러움 통과로 확대하지 않는다.

호스트 로그에는 `remote-render`가 없다. 코드상 호스트가 보는 게스트는 `HostAuthorityRemoteCharacter`의 LateUpdate snapshot 보간 경로가 아니라 `HostAuthoritativeCharacter`를 권위 시뮬레이션에서 FixedUpdate 60Hz로 직접 움직이는 경로다. 따라서 호스트 화면의 게스트에는 게스트 클라이언트 원격 모델과 같은 렌더 프레임 보간 계층이 확인되지 않는다. 이것은 “조금 덜 부드러움”의 후보 경로지만, 이번 로그에는 호스트 권위 액터의 프레임별 시각 이동 계측이 없으므로 직접 원인으로 확정하지 않는다.

## 판단

수치상으로는 일반 빌드·두 PC·2인 환경의 입력 기준선을 확보했다.

- 게스트 Update 처리율이 회복됐다.
- 새 고유 command 생성률이 호스트 권위 tick 진행률과 일치했다.
- 실제 소비율은 99.461%, fallback은 0.539%였다.
- 호스트 입력 준비, Jump 첫 삽입, 송신, Pump 큐에 새 회귀가 없었다.

이 결과는 두 PC 2인 조건의 입력 공급·소비 기준선에만 적용한다. 4인 전체 성능 해결이나 Development/Profiler가 게스트 저하의 단독 원인이었다는 결론으로 확대하지 않는다. 원격 표시 부드러움은 통과로 판정하지 않으며, 다음 분석 대상은 입력 규칙이 아니라 호스트 권위 게스트의 렌더 표시 경로와 일회성 snapshot 도착 지터다.
