## 문제와 구현

퀘스트 완료와 레벨업은 한 객체의 상태만 바꾸지 않는다. 다음 퀘스트의 활성 상태와 UI 알림도 함께 바뀐다. 발행자가 이 객체들을 모두 직접 참조하면 새 기능을 추가할 때 발행자의 코드도 계속 고쳐야 한다. 그래서 사건을 타입으로 구분하고, 해당 타입을 구독한 객체가 자기 상태를 갱신하게 했다.

이벤트 매니저는 이벤트 타입을 키로, 구독 함수 목록을 값으로 보관한다. 객체가 이벤트를 구독하면 해당 타입의 함수 목록에 처리 함수를 등록한다. 퀘스트 완료, 레벨업, 트리거 진입 같은 사건이 발생하면 발행자가 이벤트 데이터를 보내고, 이벤트 매니저가 그 타입을 구독한 객체에 전달한다. 새 사건을 추가할 때 기존 발행 객체가 모든 수신 객체를 알 필요가 없도록 한 구조다.

예를 들어 퀘스트 완료 이벤트를 받는 객체는 다음 퀘스트의 활성 상태를 갱신하고, 트리거 이벤트를 받는 객체는 안내 문구나 상호작용을 실행한다. 플레이어의 행동은 상태 클래스로 구분했다. 몬스터의 행동 단계는 Behavior Tree가 선택하고, 추적 중의 실제 이동 방향은 Context Based Steering이 계산한다.

몬스터는 주변 여러 방향으로 레이를 쏜다. 각 방향에 대한 플레이어 추적 선호도와 장애물에 가까워질수록 커지는 위험도를 별도 맵에 담는다. 위험도를 선호도에서 뺀 결과로 방향별 가중치를 구하고, 가중치가 적용된 벡터를 합쳐 최종 이동 방향을 결정한다.

```text
퀘스트 완료 → 이벤트 발행 → 이벤트 매니저 → 퀘스트 UI·관련 객체 갱신
몬스터 추적 → 방향별 선호도·위험도 계산 → 이동 방향 선택
```

## 행동 선택과 조향을 나눈 이유

Behavior Tree는 몬스터가 추적할지 다른 행동을 할지 고른다. 추적이 선택된 뒤의 방향은 Context Based Steering이 계산한다. 몬스터가 주변에 쏜 레이에서 장애물까지의 거리가 짧을수록 해당 방향의 위험도가 커진다. 플레이어 쪽으로 가려는 선호도에서 위험도를 빼고 방향 벡터를 합치면, 추적 목표와 장애물 회피를 같은 방향 계산에 넣을 수 있다. 몬스터가 일정 거리 안으로 들어왔을 때 옆으로 도는 행동은 행동 선택 조건에서 구분할 수 있다.

이벤트 전달과 몬스터 조향은 서로 다른 문제지만, 둘 다 판단과 실행을 분리했다. 이벤트 매니저는 사건의 수신 대상을 연결하고, 이동 컴포넌트는 Behavior Tree가 고른 상태 안에서 실제 방향을 계산한다.
